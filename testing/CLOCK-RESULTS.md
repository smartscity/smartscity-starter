# 时间回拨专项（2026-10-25）

此前不完整；本次新增 **23 个 Java/JUnit 用例**，补齐下表的软件故障场景，并修复启动数据库校时的两个问题：整数溢出可能误接受极端时间值；SQL NULL 未明确拒绝。

**PASS：本轮共 65 个不同功能用例通过，0 失败、0 跳过。**核心与适配层回归 51 个；隔离 MySQL/ZK 故障回归 57 个（含重复项），用时 36.03 秒，隔离服务已清理。生产打包、依赖边界、元数据和 Java 9 字节码检查通过；实际运行 JDK 为 21.0.12.1，不代表 JDK 9 已实测。

| 覆盖 | 验证内容 |
|---|---|
| 锚点与阈值 | 累计小幅偏移仍按最初锚点计算；±1000ms 接受，累计 ±1100ms 停发；恢复墙钟也不恢复已失败实例 |
| 采样与暂停 | 采样前后暂停、连续 3 次不稳定采样、负时间跨度、负 nanoTime 起点及有符号计数跨界 |
| 休眠模型 | 两个时钟一起推进可继续；仅一个推进超过阈值则拒绝；这是注入模型，不是整机休眠实测 |
| 缓存与限额 | 满缓存空闲时也检测故障；领取后校验失败的 ID 丢弃；空缓存 4 个等待者遇回拨退出；耗尽当前秒后不借未来秒、不因墙钟变化延长等待 |
| 并发与布局 | 普通、高吞吐、JS 15/16/17 位序列共 5 种布局；每种 4 消费者在偏差交替时发出 2048 个唯一 ID，故障恢复后再调用 400 次均拒绝 |
| 编码边界 | Epoch 前拒绝，时间字段耗尽时缓存中的 ID 也不再返回；逻辑时间加法溢出拒绝 |
| 数据库校时 | 前后偏差、慢查询、查询中墙钟跳变、缺行/NULL/极端值；失败关闭连接、语句和结果集，已申请 Worker 标记 OFFLINE |

## 运行

无需数据库，使用构建 JDK 21：

```sh
./mvnw -pl smartscity-id-spring-boot-autoconfigure -am test \
  -Dtest=ClockRollbackTest,ClockRollbackConcurrencyTest,ClockValidationTest \
  -Dsurefire.failIfNoSpecifiedTests=false
```

隔离故障入口也包含这 23 个用例，见[测试清单](TEST-INVENTORY.md)。测试只注入 `TimeSource` 和 JDBC 响应，不改宿主机时间；无持续运行和 benchmark。

## 复审与边界

沿用现有 `TimeSource` 测试端口；测试线程与夹具负责资源清理。`MonotonicClock` 负责采样校验，generator 持有终止状态；数据库响应和算术检查归 `JdbcWorkerRepository`。未新增生产模式、依赖或测试钩子；Worker 生命周期、运行期零 JDBC、布局和失败策略不变。

本专项验证软件可控故障模型。实际 NTP 调整、整机 suspend、虚拟机快照恢复和迁移仍 **NOT_RUN**；两个时钟同时同幅异常不在本地差值检测能力内。已经通过最终检查的在途调用不能被原子撤回；Worker 取模及同秒复用边界仍按原契约。
