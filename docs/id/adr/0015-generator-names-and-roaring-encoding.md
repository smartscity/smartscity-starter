# ADR 0015: Generator names and explicit Roaring storage encoding

Status: ACCEPTED / IMPLEMENTED_UNRELEASED, 2026-11-04. Authority: the user's implementation and benchmark specifications.

The stable API remains IdGenerator.getUniqueId/parse/snapshot/close. BufferedIdGenerator owns the existing producer, ring, clock and lease without a new hot-path strategy branch. CachedUniqueIdGenerator remains a deprecated delegating adapter, including usingClock. DefaultUniqueIdGenerator remains a deprecated single-owner cursor for existing callers; it was never an IdGenerator. SequenceIdGenerator adds a synchronous lifecycle-managed front end around that same cursor, with a bounded interruptible lock and per-call clock validation. It borrows logical seconds on sequence exhaustion, not a third allocation algorithm. This new path has no ring or producer and its latency is not expected to match buffered generation. Factories still allocate exactly one worker and default to buffered standard IDs.

IdEncoder is a stateless reversible representation port. IdentityIdEncoder preserves positive IDs. RoaringIdEncoder v1 permutes all 63 bits of a positive 30/18/15 payload; epoch is not changed. Metadata uses `roaring-30-18-15-v1` and is external to the long; unknown versions fail explicitly. Other bit layouts are not supported by this encoding.

RoaringIdGenerator is a non-owning decorator, never an allocator. Its constructor accepts a standard 30/18/15 delegate by contract; arbitrary IdGenerator implementations do not expose layout introspection. parse decodes before delegating. close closes only the view, never the shared delegate; the application owns delegate cleanup. snapshot is explicitly the delegate's allocation observation, including readiness, and excludes permutation/view failures. A closed view rejects new generation; in-flight calls may complete. Default Boot injection stays standard. Existing-ID encoding is preferred when one business ID is stored in both SQL and a Bitmap.

Pattern review: use a decorator for optional representation, keep the producer cursor invariant in its existing owner, use a small encoder interface for actual identity/permutation alternatives. Do not add strategy checks to buffered generation, coordination resources, modules, production Roaring dependencies or a generic generator hierarchy. Preserve deprecated signatures and existing lifecycle regression assertions. Version/layout assumptions, same-version snapshots, membership/deletion and migration must be verified independently of speed.
