# ID CI database and restart review

## Root causes and corrections

| Failure | Evidence and cause | Correction |
|---|---|---|
| Restart fixture rejected CI database | The fixture requires owned loopback port 13367, but the CI service was published on 3306 | Publish the build job's owned MySQL service on 13367 and use that URL; preserve the fixture guard |
| Standalone ZooKeeper/MySQL test lacked tables | The test relied on MySqlIntegrationTest executing first; JUnit class order is not a schema lifecycle | Reuse one test-only schema initializer from each MySQL consumer, including the standalone ZooKeeper case |
| Connection count changed during snapshots | Accepted ADR-0013 permits one asynchronous read-only capacity query per 30 seconds; tests counted it as forbidden issuance JDBC | Account for the named capacity reader separately; assert issuance requests no observations, repeated snapshots share one completed read, and lifecycle connections remain unchanged during traffic/reconnect |
| Immediate post-close connection assertion | Close interrupts the asynchronous capacity reader; the reader owns eventual connection cleanup | Await bounded SDK thread termination before asserting zero borrowed connections on every restart, rather than once per 100 cycles |
| Concurrent Roaring uniqueness test occasionally timed out | The default 10 ms operation budget is not a scheduler guarantee on a shared runner | Set an explicit one-second budget in this concurrent uniqueness case; keep all 4000 uniqueness/decoding/ownership assertions and the separate deadline tests |

The production default wait budget, allocation protocol, database schema, monotonic worker cursor, no-reuse policy, generation path and shutdown contract are unchanged. No production Java source is modified by these CI corrections. The existing uncommitted balanced-Roaring changes are excluded from the remote validation patch.

## Verification procedure

The old standalone ZooKeeper/MySQL test was reproduced failing against a newly owned, empty MySQL database with the missing smartscity_id_group table. The corrected test passed alone against another fresh database; both owned servers were terminated and their ports released.

Run the existing owned fault harness with `python3 test/run-destructive.py --run --restart --output <new-directory>` under build JDK 21. CI supplies independent MySQL and PostgreSQL services, executes the full reactor with restart opt-in, then runs `python3 test/check-ci-evidence.py` alongside artifact/repository gates. The evidence gate requires 43 real database/coordination/restart cases across the domain and both starter generations, with no skips. Broader suite totals and any intentionally excluded destructive cases must be reported separately.

Retain the preceding failures and exact tested revision. A successful test gate is not a long-duration soak, arbitrary JVM/OS certification, deployment or performance guarantee.
