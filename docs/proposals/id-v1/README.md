# 分布式 ID 方案 v0.9 · 精简版

2026-10-25：v0.8 方案方向已确认；本版压缩表述、补齐边界。默认参数及实施步骤已获确认，2026-10-25 开始实施；性能测试明确排除。

## 1. 格式与容量

秒级 Snowflake，Epoch 固定为 **2026-01-01T00:00:00Z**。

`ID = (秒差 << (Worker位数 + 序列位数)) | (Worker << 序列位数) | 序列`

| 档位 | 零位 / 时间 / Worker / 序列 | Worker 槽位 | 每 SDK 每秒容量 | Epoch 起总寿命 |
|---|---|---:|---:|---:|
| 普通（默认） | 1 / 30 / 18 / 15 | 262,144 | 32,768 | 约 34 年 |
| JavaScript | 1 / 28 / 10 / 15 | 1,024 | 32,768 | 约 8.51 年 |
| 高吞吐 | 1 / 30 / 16 / 17 | 65,536 | 131,072 | 约 34 年 |

JavaScript 档可改为 **27/10/16：65,536 ID/s、4.25 年**，或 **26/10/17：131,072 ID/s、2.13 年**；有效位始终为 53 位。每借一个时间位，容量翻倍、寿命减半，寿命从 Epoch 起算。

同组固定布局、Epoch 和 Worker 分配源；不同组或不同布局不保证裸 ID 互不重复。字段越界、时间耗尽直接失败，禁止截断回绕；返回正数 long，保留 0。容量是 ID/s，不是并发线程数；业务 TPS 按每笔 ID 用量换算，吞吐仍需实测。

## 2. Worker 与数据库

- **启动：**直接 INSERT WorkerNode，提交确认后取自增原始 ID，`Worker = 原始ID % 2^Worker位数`，本次 SDK 固定使用。不先查空闲 Worker。
- **运行：**不访问 MySQL，无使用期限。关闭时先停发、停线程，再由 shutdown hook 限时尝试标记退出；kill -9 可能不执行。
- **普通/高吞吐档：**用大 Worker 空间延长回绕周期。前提是回绕前旧实例已退出、历史发号秒已过去；不能保证跨越整圈的旧实例与新实例互斥。
- **数据库：**默认 MySQL，组件内置 TiDB/PostgreSQL 适配，用户只配置类型、连接与驱动。禁止自增序列回退；数据库恢复或切换也必须维持分配连续性。

数据库状态仅供观察，不证明实例存活。回绕预警根据启动事件与实例指标汇总，不让 SDK 运行中查库。

## 3. JavaScript 档的 ZK 条件

按编码 Worker 创建临时节点 `/id/{group}/workers/{Worker}`，成功后才初始化缓存。冲突时启动阶段重新 INSERT 并有界重试；通信失败不视为空闲。**ZK 只管占用和会话，保留心跳，不逐秒写发号进度。**

断连暂停发号；同一会话恢复后，确认仍持有节点且时间正常才恢复。会话过期则旧生成器终止、缓存作废；新建 SDK 才重新执行启动分配，不在旧实例运行中自动查写 MySQL。占用结果不确定时禁止就绪，失败启动须释放资源。

使用方负责流量均衡、最忙 SDK 的峰值、ZK 可用性及滚动发布余量；新旧实例和未过期会话合计不能超过 1,024 个槽位。**同秒复用、过期旧进程恢复仍有重复风险**，均衡流量不能消除这些风险；本组件不承诺无条件唯一性。

## 4. 时间与等待

`发号时间 = 启动墙钟锚点 + nanoTime 经过时长`

- 启动与数据库时间校验，计入网络时延；无法校验或偏差超过 **1 秒（可配置）**，拒绝就绪。
- 运行只比较本地墙钟与推算时间；小偏差不改变秒游标，超阈值停发。nanoTime 没有日历时间，也不能跨重启延续。
- 秒内序列递增；耗尽后生产者等下一秒，不借未来秒。消费者可继续领取已有缓存，缓存为空才短时等待，超时失败。
- 等待共用一次调用的总预算，支持中断，不无限忙等；关闭、时间异常或占用失效直接失败。时间异常停发后须重建 SDK，不自动重锚定。

**已确认默认参数：等待 10ms、缓存 16,384 槽、低水位 50%，均可配置。**短时等待吸收调度抖动，不保证等到下一秒，也不能弥补持续超载。

## 5. RingBuffer、无锁与 false sharing

沿用 BitsAllocator、WorkerIdAssigner、DefaultUniqueIdGenerator、CachedUniqueIdGenerator、RingBuffer、BufferPaddingExecutor 的职责。缓存模式由**单后台生产者**独占秒/序列，业务线程只消费，不混用直接发号路径。

数据：`long[] ids`、`long[] slotSequence`，容量 N 为 2 的幂；消费游标 CAS，生产游标单线程拥有。槽位轮次初值为下标，游标从 0 开始，数组下标为 `position & (N−1)`。

1. **生产：**acquire 读到轮次=p 才可写；先写 ID，再 release 发布轮次=p+1。
2. **消费：**acquire 读到轮次=c+1 后，只有 CAS 消费游标 c→c+1 成功者才能读 ID。
3. **回收：**读完后 release 写轮次=c+N，允许下一圈覆盖。领取后发生失败则丢弃 ID、回收槽位，不放回重发。

轮次防止跨圈误认，CAS 防重复领取，acquire/release 保证可见性。游标不能溢出归零。无显式锁不等于严格 lock-free：已领取者暂停仍可能阻塞槽位复用；并发返回顺序不保证递增。缓存时间是生成时间，不等同业务调用时间。

生产/消费游标及统计字段分开并填充，减少 false sharing；实际布局和收益需测量，padding 不能解决同一游标的真实 CAS 竞争。使用公开 JDK API，不用 Unsafe；避免装箱、逐 ID 日志及临时集合。

填充信号合并，只保留一个生产者，异常后清理状态并重新检查需求，防止任务堆积和丢失唤醒。关闭须唤醒等待者；首次填充完成后才就绪。

## 6. 可观测与验证

指标：发号量、失败原因、等待/超时、延迟、缓存余量/年龄、填充耗时、时间偏差、就绪及 ZK 状态。启动事件记录布局、原始 ID、Worker；避免高基数指标标签。

验证重点：并发领取与跨圈、秒切换与溢出、回拨/暂停、重启/kill -9、MySQL 断连、ZK 断连/过期、启动失败资源回收。已披露风险须复现并标明边界，不能算作防重通过。目标机器 10 万 ID/s 的持续性能另行授权测试。

依据：[源码审计](legacy-input-audit.md)、[nanoTime](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/System.html#nanoTime())、[内存可见性](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/invoke/VarHandle.html)、[ZK 会话](https://zookeeper.apache.org/doc/current/zookeeperProgrammers.html#ch_zkSessions)、[JS 安全整数](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer)。实际实现与验证结果见[门禁记录](../../../testing/GATE-RESULTS.md)。

## 7. 实施顺序（已确认）

| 步骤 | 工作 | 验收重点 |
|---|---|---|
| 1. 契约与配置 | 确定 API、异常、配置键和表结构；启动原子校验同组布局/Epoch，Worker 仍直接 INSERT | 同组配置冲突拒绝启动；范围、等待、中断、关闭语义清晰 |
| 2. 发号核心 | 位编码/解析、单调时钟、序列和边界检查 | 三档及 JS 变体、秒切换、回拨、耗尽 |
| 3. 缓存与并发 | RingBuffer、单生产者、补充调度、有限等待、缓存行隔离 | 多线程不重复领取、跨圈、超时、异常恢复与关闭 |
| 4. Worker 适配 | MySQL 自增/退出更新、ZK 原子占位与会话处理；TiDB/PostgreSQL 方言 | 真实数据库/ZK 下启动、冲突、重启与故障；运行期无数据库访问 |
| 5. Starter 与运维 | 自动配置、用户 Bean 退让、指标/就绪、最小示例 | 核实后的 Boot/JDK 组合实际启动；依赖和资源关闭正确 |
| 6. 整体验收 | 多实例、滚动发布、故障场景；另行授权后测持续 10 万 ID/s | 报告正确性、剩余风险、兼容范围及实测性能 |

JDBC/ZK 适配先放现有 AutoConfigure 模块的独立包；Core 只依赖 API/SPI/JDK，Starter 仅聚合。内部适配边界不要求使用方编写 SPI。

已获准按上述顺序实现并做正确性验证；性能测试暂停，提交及发布未获授权。
