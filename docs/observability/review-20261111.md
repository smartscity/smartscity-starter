# Observability implementation review: 2026-11-11

Scope: the complete first-release implementation, with emphasis on identity propagation, masking, concurrency, resource ownership and performance mechanisms. The accepted parent/current wire mapping remains unchanged. This review found defects that were not covered by the initial 46 passing tests; that initial result was not sufficient to declare the implementation fully reviewed.

## Findings and corrections

| Priority | Confirmed finding | Correction | Regression evidence |
|---|---|---|---|
| P1 | With a native tracer but no Smartscity scope, an outbound invocation could reuse its ambient parent as its current span | Reuse only when the current HTTP observation owns the exact carrier and native span; otherwise create a distinct native child | TracerProviderTest reproduces the previous binary failure, checks distinct sibling IDs, downstream parent mapping, scope restoration and exact native observation ownership |
| P1 | The supplied Logback include did not bind custom sensitive fields or indexed YAML literal lists; it also ignored the explicit service-name override and record limit | Bind settings before Logback starts; preserve literal commas through an internal encoding and retain safe empty-dictionary defaults | LogbackConfigurationTest reproduces the old custom-field leak and verifies actual XML startup on all three Boot versions |
| P1 | Destructive credential replacement could remove part of a configured literal before the literal matcher ran, exposing its suffix | Credential and literal rules inspect the same original text; invocation-owned RedactionRanges merges coverage before rendering | Old compiled sanitizer returned PARTIAL_SECRET_LEAK=true for synthetic password=abc,def with literal abc,def; the new mixed-rule regression also covers a literal matching the token field name |
| P2 | Malformed JSON Pointer rules were silently ineffective, and the valid empty root pointer was ignored | Validate pointer syntax/bounds at construction and mask the entire JSON document for the root pointer | IntegrationPolicyTest checks invalid rules and whole-document redaction |
| P2 | A duration below one millisecond could become join(0); concurrent closers could return before cleanup or thread exit | Preserve nanosecond deadlines, share completion and the remaining join budget, wake via the bounded queue, force socket close on deadline/interruption | ConcurrencyReviewTest: concurrent producers/closers, submillisecond close, preserved interruption and worker/queue cleanup |
| P2 | Exchange completion read capture state outside its monitor; direct abort did not prevent subsequent capture allocation | One monitor owns capture, completion, reset and abort transitions; completion hooks and reservations release once | Concurrent completion/reset/abort test, with no post-completion reservation |
| P2 | An application Error could bypass client completion and leave captured bytes/native child ownership unfinished | Preserve and rethrow the original Error while completing cleanup; the Servlet adapter records failure and defers final status to its completion fallback | HttpLifecycleTest verifies original AssertionError identity, scope restoration and released client capture |

The suspected “interrupt always closes this sender's channel” issue was **not confirmed**: the executed JDK 21 implementation skips the interruptible write hook for nonblocking DatagramChannel writes. It is not counted as a defect. Queue wake-up still simplifies shutdown and removes periodic idle wake-ups. Final thread exit can lag a timeout because OS scheduling is not bounded; socket cleanup and stopped acceptance do not depend on an unbounded join.

## Ownership and pattern decisions

| State / problem | Decision | Reason |
|---|---|---|
| Parent/current native span ownership | Reuse the tracing adapter and inspect the actual HTTP observation | An ambient current span alone does not prove it belongs to this invocation |
| Overlapping sanitization policies | Add invocation-local RedactionRanges value/accumulator | One owner maintains original offsets and coverage; immutable compiled matchers remain shared |
| Early Logback configuration | Environment adapter, no global mutable policy singleton | Logback starts before application beans; scalar and indexed properties must agree |
| Capture completion and abort | Keep one exchange owner with a synchronized terminal transition | A completion flag alone did not protect the related capture state |
| UDP acceptance and cleanup | Keep one bounded queue and one socket-writing consumer; share shutdown completion | No additional executor, retry queue or native sender is introduced |

The range object is mutable only within one sanitization invocation. Compiled dictionaries and copied field/path rules are read-only after startup. Queue acceptance, local socket write and remote delivery remain distinct outcomes. Application tracers, executors and supplied registries remain application-owned.

## Performance review

| Source-confirmed mechanism | Effect / limit |
|---|---|
| Body capture disabled/unapproved | Return the original response writer/stream; avoid an unnecessary UTF-8 writer buffer and tee work |
| Logging disabled at the logger | Skip event construction, source-stack collection and body reservation |
| Single-byte capture | Append directly without allocating one-element arrays |
| Empty/no-match literal policy | No coverage array or rendered string copy; range storage is lazy |
| Wire grammar | Reuse compiled field/tag/level patterns |
| Source location | Capture one stack snapshot instead of two |
| UDP idle consumer | Blocking take; no once-per-second poll wake-up |
| UDP sends | Nonblocking producers with respect to capacity; bounded batching and packet length; lock contention remains possible |
| Resource budget | Capture reservations bound raw captured bytes, not the entire JSON tree, encoder scratch space or process heap |

These are code/ownership conclusions. Throughput, P99, CPU use, total heap and compressed log size are **NOT_MEASURED**. No performance benchmark was run or inferred from correctness-test timing. Micrometer still owns the gauge/function-meter polling scheduler; “single thread” refers specifically to UDP socket writing.

## API evidence

Spring documents HTTP-client observations and their ClientRequestObservationContext in its [observability reference](https://docs.spring.io/spring-framework/reference/integration/observability.html). The exact provider/context methods used here were additionally checked against the resolved library APIs and real provider objects. Java's general interruption contract is described in [InterruptibleChannel](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/channels/InterruptibleChannel.html); the nonblocking distinction above was checked in the executed JDK's DatagramChannelImpl source.
