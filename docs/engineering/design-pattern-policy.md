# 设计模式策略

先辨认职责、状态和真实变化轴，再选择模式。不能为了展示模式预建空策略、工厂或通用事件总线。

| 触发条件 | 实现前检查 |
|---|---|
| 向核心类新增至少 3 个相关可变字段 | 是否应由独立对象拥有不变量和转换 |
| 同一状态/模式出现第三个同类分支 | State、Strategy 或集中转换是否更清晰 |
| 对象混入多组不同变化原因 | 是否将组装、算法、I/O、观察分离 |
| 构造需至少 4 个重要协作者 | Factory / Assembler 与 Composition Root |
| 公共 API 至少 5 个参数或多个可选组合 | 不可变配置或 Builder 的合法性校验 |

非简单变化记录“问题 / 候选模式 / 采用或不采用 / 理由”，说明其如何保护状态、技术边界或稳定 API。触发评估不自动产生审批要求；已授权的内部职责调整正常执行。

## 当前实现的取舍

| 问题 | 候选模式 | 当前决定 | 理由 |
|---|---|---|---|
| 框架与算法分离 | Adapter / Port | TimeSource / WorkerLease + JDBC/ZK 适配 | Core 只读取时钟与本地占用状态，不直接执行 I/O |
| Spring 对象组装 | Factory / Composition Root | IdGeneratorFactory | 集中有界启动、失败清理与资源归属 |
| 多个布局与参数 | Builder | GeneratorOptions | 不可变配置并集中验证约束 |
| 数据库差异 | Adapter | 内置 DatabaseDialect | 使用方仅配置类型，避免要求自写 SPI |
| 生命周期分支 | State | 集中状态转换，不引入 State 子类 | 状态数量有限；ZK 回调与发号状态有明确 owner |
| Starter 使用入口 | 依赖聚合 | 使用轻量 Maven 模块 | 不需要持有状态的 Facade 类 |

后续复审模式是否集中真实不变量，而不是只搬移字段；避免类数量、行数或模式数量驱动设计。
